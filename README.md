# Gwent Multiplayer

Браузерный «Гвинт» для двух игроков на основе [asundr/gwent-classic](https://github.com/asundr/gwent-classic).
Исходное поле, карты, звуковые эффекты и редактор колод сохранены. Вместо ИИ играет другой человек.

Чтобы играть с друзьями через Интернет, разместите проект на **Render или Railway**:
готовые конфигурации и пошаговая инструкция находятся в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
Один сервис запускает и сайт, и игровой сервер; хостинг выдаёт публичный адрес с HTTPS.

## Запуск

Нужен Node.js 22.18 или новее в ветке 22 либо Node.js 24+.

```sh
npm ci
npm start
```

Оставьте терминал с `npm start` открытым и перейдите в браузере на
**http://localhost:3000**. Браузер нужно открыть самостоятельно.
Адрес `0.0.0.0` означает привязку сервера ко всем сетевым интерфейсам;
для браузера на том же компьютере используйте `localhost`.

В Windows выполните `npm ci` и `npm start` в PowerShell из папки проекта.
Чтобы открыть игру командой, во втором окне PowerShell выполните:

```powershell
Start-Process 'http://localhost:3000'
```

Оба игрока открывают адрес одного запущенного сервера. Для второго компьютера
в той же локальной сети используйте IPv4-адрес компьютера с сервером,
например `http://192.168.1.10:3000`; его можно посмотреть командой `ipconfig` в Windows.
Для игроков из разных сетей используйте [развёртывание на Render или Railway](docs/DEPLOYMENT.md).

Порт и адрес привязки можно задать через `PORT` и `HOST`;
например, `PORT=8080 npm start` в Bash. В PowerShell:

```powershell
$env:PORT = '8080'
npm start
```

Тогда открывайте `http://localhost:8080`.
Для разработки с автоматическим перезапуском сервера: `npm run dev`.
Открытие HTML как локального файла не подходит: для сетевой игры нужен сервер.

## Как играть

1. Укажите имя и создайте комнату. Другой игрок найдёт её в общем списке или введёт шестизначный код.
2. Когда в комнате два человека, обоим открывается существующий редактор колод. На выбор даётся 30 секунд по единому серверному таймеру.
3. Подтвердите колоду. Если оба готовы, партия начинается сразу. По истечении времени сервер принимает текущую допустимую колоду; при недопустимой или отсутствующей колоде использует стандартную колоду Северных королевств.
4. В начале партии каждый игрок может заменить до двух карт. Выбирайте карты либо нажмите «Готово», чтобы оставить руку.
5. Выберите карту и подсвеченный ряд; для погоды и «Казни» подтвердите применение в просмотре карты. «Чучело» требует выбора своего обычного отряда. Лидер и кнопка «Пас» завершают ход.

Правила, фракции и способности карт взяты из исходной игры. Сервер рассчитывает эффекты,
очередность ходов и результаты раундов. Каждый браузер получает только свою руку,
открытые карты стола и сброса, а также количество карт соперника.

Настройки звука и колоды сохраняются в браузере. При обновлении страницы или кратком
обрыве связи место в комнате восстанавливается в течение 30 секунд. После этого комната
закрывается, а оставшийся игрок возвращается в лобби. Выход из комнаты завершает текущую партию.

## Проверки

```sh
npm test
npm run test:browser
npm run test:browser:https
```

Серверные тесты проверяют комнаты, таймер, восстановление соединения, приватность рук,
допустимость команд, все сочетания пяти фракций и активируемые способности лидеров.
Браузерные тесты используют независимые сессии двух игроков и настоящий сервер.
На Linux используется установленный `/usr/bin/chromium`, если он доступен;
можно указать путь через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.
На другой машине установите браузер командой `npx playwright install chromium`.
Команда `test:browser:https` дополнительно проверяет игровые сценарии через настоящий
HTTPS-прокси и защищённое соединение WebSocket. Для этой проверки нужен OpenSSL;
она использует временный локальный сертификат и не меняет TLS-настройки размещённой игры.

## Развёртывание и устройство

Статика находится в `public/`, WebSocket и комнаты — в `server.cjs`.
`server/game-engine.cjs` запускает оригинальные правила в отдельном JSDOM-контексте на матч,
а `server/engine-adapter.js` переводит интерактивные решения в команды двух игроков.
Исходный редактор колод продолжает работать в браузере; игровое состояние задаёт сервер.

В репозитории есть `Dockerfile` и `render.yaml` для размещения на Render или Railway.
Хостинг запускает сервер, назначает `PORT` и обслуживает HTTPS и WebSocket;
подробные шаги и проверка подключения — в [инструкции развёртывания](docs/DEPLOYMENT.md).
Endpoint `/health` используется для проверки работоспособности.
Комнаты хранятся в памяти одного процесса: **нужен один экземпляр сервиса**,
а перезапуск, новое развёртывание или остановка сервиса закрывают текущие партии.
В этой версии нет учётных записей, базы данных, рейтинга и согласованного реванша.
Музыка из YouTube не подключается; локальные звуковые эффекты сохранены.
