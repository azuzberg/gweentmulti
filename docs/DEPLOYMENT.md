# Игра через Интернет: Render или Railway

После размещения оба игрока открывают одну публичную ссылку вида
`https://gweentmulti.onrender.com` или `https://gweentmulti.up.railway.app`.
Один создаёт комнату, другой входит по коду или из списка комнат.
Игроки могут находиться в разных сетях. Открывать порт на домашнем роутере не нужно.

В репозитории подготовлены:

- `Dockerfile` — установка зависимостей и запуск Node-сервера с игровыми файлами.
- `render.yaml` — конфигурация веб-сервиса Render.
- `/health` — HTTP-проверка готовности сервера.

Проект запускается **одним веб-сервисом с одним экземпляром**.
Сайт и WebSocket `/ws` используют один домен. Отдельный сервис для браузерной части не требуется.
Секреты, токен GitHub внутри приложения и база данных для этой версии игры не нужны.

## Render: через готовую конфигурацию

1. Войдите на [render.com](https://render.com) и подключите GitHub.
2. Нажмите **New + → Blueprint** и выберите репозиторий
   [azuzberg/gweentmulti](https://github.com/azuzberg/gweentmulti), ветку `main`.
   Если репозиторий не появляется, разрешите Render доступ к нему в настройках подключения GitHub.
3. Render прочитает `render.yaml`. Проверьте предложенный сервис и выбранный тариф перед созданием.
   Название сервиса можно изменить.
4. Запустите создание Blueprint и дождитесь успешной сборки и запуска сервиса.
5. Откройте сервис и перейдите по выданной ссылке `https://…onrender.com`.
   Этот адрес отправьте второму игроку.

Render собирает контейнер из `Dockerfile`. Свою команду сборки браузерной части вводить не нужно.
HTTPS и проксирование WebSocket предоставляет хостинг.

### Render: создание сервиса вручную

Если создаёте сервис через **New + → Web Service**, используйте следующие параметры:

| Настройка | Значение |
| --- | --- |
| Repository | `azuzberg/gweentmulti` |
| Branch | `main` |
| Language / Runtime | `Docker` |
| Root Directory | Оставить пустым |
| Dockerfile Path | `./Dockerfile` |
| Docker Command | Оставить пустым: запуск указан в `Dockerfile` |
| Health Check Path | `/health` |
| Instances | `1` |

`PORT` назначает Render. Сервер слушает `0.0.0.0`, поэтому он доступен прокси хостинга.
Не задавайте `HOST=localhost` и не заменяйте платформенный `PORT` произвольным портом.

На бесплатном тарифе Render может останавливать сервис после простоя. Следующее открытие
разбудит его, но загрузка может занять время, а комнаты предыдущего процесса исчезнут.
Для регулярных партий выбирайте тариф, который поддерживает постоянно работающий сервис.
Перед выбором платного тарифа проверьте стоимость в интерфейсе Render.

## Railway

1. Войдите на [railway.com](https://railway.com) и подключите GitHub.
2. Нажмите **New Project → Deploy from GitHub repo** и выберите
   `azuzberg/gweentmulti`. В настройках источника сервиса укажите ветку `main`.
3. Railway автоматически обнаружит `Dockerfile` в корне репозитория.
   Команды сборки и запуска вручную переопределять не нужно. В логах сборки должна появиться
   строка `Using detected Dockerfile!`.
4. В **Settings** сервиса задайте путь проверки готовности (**Healthcheck Path**) `/health`.
   Для **Restart Policy** оставьте **On Failure**, максимум перезапусков — `10`.
   В настройках реплик оставьте **одну реплику в одном регионе**.
   Примените изменения и дождитесь успешного запуска.
5. В настройках сервиса откройте **Networking → Public Networking** и нажмите
   **Generate Domain**. У сервиса должен появиться публичный адрес `https://…up.railway.app`.
6. Откройте этот адрес и отправьте его второму игроку.

Railway предоставляет HTTPS и поддерживает WebSocket. `PORT` назначает платформа;
сервер использует его автоматически. Если при создании домена интерфейс просит целевой порт,
укажите порт, на котором запущен процесс: его можно посмотреть в логах сервиса.
Проверка `/health` в Railway выполняется при развёртывании, прежде чем платформа направит
пользователей на новую версию; она не заменяет постоянный мониторинг.

Для непрерывной игры отключите остановку сервиса при простое (Serverless / App Sleeping),
если такая настройка включена. Условия пробного периода и стоимость проверьте в интерфейсе Railway.

## Переменные сервиса

Для обычного запуска на Render или Railway дополнительные переменные не нужны.
Если меняете настройки вручную, используйте панель переменных своего сервиса:

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт процесса. Оставьте значение, назначенное хостингом. |
| `HOST` | Адрес привязки; используйте `0.0.0.0`. В Docker и конфигурации Render уже задан. |
| `NODE_ENV` | В контейнере задано `production`. |
| `PUBLIC_URL` | Необязательный публичный адрес вида `https://play.example.com` для проверки подключения WebSocket при нестандартном прокси. Для стандартного размещения не требуется. |
| `MAX_ROOMS` | Максимальное количество комнат; по умолчанию `20`. Можно уменьшить на маломощном тарифе. |
| `MAX_SESSIONS` | Максимальное количество игровых сессий; по умолчанию `500`. |

Сервер также использует `RENDER_EXTERNAL_URL` или `RAILWAY_PUBLIC_DOMAIN`, если платформа их предоставляет.
Менять адрес в браузерных файлах после получения домена не нужно.

## Проверка после запуска

1. Откройте публичный адрес сервиса с `/health` в конце, например
   `https://gweentmulti.onrender.com/health`. Должен вернуться HTTP 200 и ответ `{"ok":true}`.
2. Откройте основной адрес в обычном окне браузера и в режиме инкогнито.
   Для проверки через Интернет второй игрок может открыть его со своего устройства.
3. Введите разные имена. Создайте комнату в первом окне и войдите во втором.
4. Проверьте, что обоим открылся выбор колоды, затем подтвердите колоды.
   Сыграйте несколько ходов и убедитесь, что они отображаются у обоих игроков.

Оба игрока должны использовать **один и тот же публичный адрес**.
`localhost` ведёт на компьютер самого игрока и подходит для локальной проверки.
По публичному HTTPS-адресу браузер автоматически подключается к игровому серверу через `wss://`.

## Обновление и ограничения текущей версии

Настройте источник сервиса на ветку `main`. Если автоматическое развёртывание включено,
публикация нового коммита в этой ветке запускает сборку. Иначе используйте ручное развёртывание
в панели хостинга. После обновления проверьте `/health` и создание комнаты.

Комнаты, колоды активной партии и игровые сессии хранятся в памяти процесса.
**Перезапуск сервиса, новое развёртывание или остановка хостингом завершает текущие партии.**
Поэтому обновлять сервис удобнее между партиями. Колоды, сохранённые в браузере,
сохраняются после обновления сервера.

Не запускайте несколько реплик или несколько Node-процессов: они не разделяют комнаты.
Для масштабирования и сохранения партий при перезапуске потребуется отдельная доработка
с общим хранилищем состояния. Сейчас нет учётных записей и рейтинга; лобби доступно
всем, кто открыл публичный адрес.

## Если сайт или соединение не работает

| Симптом | Что проверить |
| --- | --- |
| Нет публичной ссылки в Railway | Создайте её через **Networking → Generate Domain**. |
| Сборка не проходит | Откройте Build Logs. Сборка должна использовать `Dockerfile` из корня репозитория и ветку `main`. |
| Хостинг сообщает о неуспешной проверке готовности | Проверьте логи, путь `/health`, `HOST=0.0.0.0` и использование платформенного `PORT`. |
| Render долго открывает первый экран | Если сервис спал, дождитесь его запуска и проверьте логи. Для постоянной доступности нужен соответствующий тариф. |
| Лобби открывается, но показывает потерю связи | Проверьте, что сайт открыт по публичному HTTPS-адресу сервиса, а в панели разработчика браузера запрос `/ws` получает ответ `101 Switching Protocols`. |
| Второй игрок не видит комнату | Убедитесь, что оба открыли одинаковый домен и запущена ровно одна реплика. |
| Комната исчезла | Проверьте, не было ли перезапуска, нового развёртывания или остановки при простое. Создайте новую комнату. |

Для своего домена добавьте его через настройки хостинга и выполните выданные им инструкции DNS.
Сертификат HTTPS выдаёт платформа. Дополнительный прокси перед приложением должен сохранять
публичный `Host` и передавать `X-Forwarded-Proto`; стандартного прокси Render или Railway достаточно.

Документация хостингов: [Docker на Render](https://render.com/docs/docker),
[Blueprint Render](https://render.com/docs/infrastructure-as-code),
[Dockerfile на Railway](https://docs.railway.com/builds/dockerfiles),
[публичный домен Railway](https://docs.railway.com/networking/public-networking),
[проверки готовности Railway](https://docs.railway.com/deployments/healthchecks).
